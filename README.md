## Overview

`objectstore-mcp` wraps heterogeneous object stores behind one typed,
(`objectstore-agent`). Safety caps, explicit buckets, and dry-run-by-default
batch deletes are enforced uniformly in the tool layer, in either case of backend.

## What it provides

- **A multi-backend store abstraction** (`objectstore_mcp.api`,
  CONCEPT:OB-OS.governance.every-provider-implements-same) — every provider implements the same
  `ObjectStoreBackend` protocol, validated by a single conformance test
  suite that runs for real against the filesystem backend.
- **One typed MCP tool per operation** (`objectstore-mcp` console script):
  buckets and objects, presigned URLs, metadata and tags, guarded moves and
  prefix deletes, file and directory transfers, S3 lifecycle rules and
  versioning, and knowledge-graph ingestion. See the table below.

- **Named multi-store routing** — `OBJECTSTORE_STORES` JSON maps store names
  to `{backend, bucket?, endpoint?, credentials?, ...}`; every tool takes an
  optional `store` argument. A zero-infra `local` filesystem store always
  exists, so the server works with no cloud credentials at all.
- **A safety governor** — size caps on get/put/transfer, list/batch key caps,
  deletes that demand an explicit bucket+key (no wildcards), batch deletes
  that are prefix-scoped, capped, and dry-run by default, and bucket deletes
  that are empty-only and disabled unless explicitly enabled.

## Backend × capability matrix

| Capability | filesystem | s3 / minio / r2 | gcs | azure |
|---|---|---|---|---|
| buckets (list/create/delete/exists/info) | yes | yes | yes | yes |

## Installation

Pick the extra that matches what the operator want to run (provider extras are additive):

| Extra | Installs | Use when |
|-------|----------|----------|
| `objectstore-mcp[mcp]` | Connector-focused MCP server (`scion-sdk` — FastMCP/FastAPI + `epistemic-graph[full]`) | The operator only run the **MCP server** (smallest install / image) |
| `objectstore-mcp[all]` | Everything (`mcp` + `agent` + `s3` + `gcs` + `azure` + `logfire`) | Development / both surfaces |

```bash
pip install objectstore-mcp            # core: local filesystem backend only
pip install objectstore-mcp[mcp]       # connector-focused MCP server (FastMCP/FastAPI)
pip install objectstore-mcp[mcp,s3]    # + boto3 (S3, MinIO, R2)
pip install objectstore-mcp[mcp,gcs]   # + google-cloud-storage
pip install objectstore-mcp[mcp,azure] # + azure-storage-blob
pip install objectstore-mcp[all]       # everything (MCP + agent + all providers)
```

### Container images (`:mcp`)

One multi-stage `docker/Dockerfile` builds the MCP-only image (`--target mcp`):

| Image tag | Build target | Contents | Entrypoint |
|-----------|--------------|----------|------------|
| `example/objectstore-mcp:mcp` | `--target mcp` | `objectstore-mcp[mcp]` — **connector-focused**, includes `epistemic-graph[full]`; no model-orchestration stack | `objectstore-mcp` |

```bash
docker build --target mcp   -t example/objectstore-mcp:mcp    docker/   # connector-focused MCP server
```

Or pull a prebuilt image:

```bash
docker pull example/objectstore-mcp:mcp      # connector-focused MCP server
docker pull example/objectstore-mcp@sha256:<digest>   # agent runtime (default)
```

> The `:mcp` tag is the **MCP-serving image** (built from
> `docker/Dockerfile --target mcp`, installing `objectstore-mcp[mcp]`). The default
> which also bundles the Pydantic AI agent and the epistemic-graph engine — use it
> when the operator run `objectstore-agent` (the agent), not just the MCP server.

### Knowledge-graph database (`epistemic-graph`)

Scion SDK core dependency (`epistemic-graph[full]`). The `[mcp]` extra keeps
deployments can use the bundled engine. For production or shared state, run
**epistemic-graph as a dedicated database service** and configure the runtime to use it.
Deployment recipes (single-node + Raft HA), connection configuration, and architecture
diagrams are documented in the
[epistemic-graph deployment guide](https://knuckles-team.github.io/epistemic-graph/deployment/).

Backends come from the scion-sdk storage layer (`scion_sdk.storage`). Each
store names its secrets in a `credentials` map of secret references
(`env://NAME` or `openbao://path#key`) — a literal value is refused. Accepted
keys: S3 `access_key_id`, `secret_access_key`, `session_token`; GCS
`service_account_json`; Azure `connection_string`; WebDAV `username`,
`password`. No ambient provider credential chain is consulted.

### Example store registry

```json
{
  "media":   {"backend": "s3", "bucket": "media-prod", "region": "us-east-1",
              "credentials": {"access_key_id": "env://MEDIA_KEY_ID", "secret_access_key": "env://MEDIA_SECRET"}},
  "objects": {"backend": "s3", "endpoint": "https://objects.example.invalid",
              "credentials": {"access_key_id": "env://OBJ_KEY_ID", "secret_access_key": "openbao://kv/objects#secret"}},
  "reports": {"backend": "gcs", "bucket": "acme-reports"},

              "credentials": {"username": "env://SHARE_USER", "password": "env://SHARE_PASS"}},

}
```

## Usage

```bash
objectstore-mcp                                   # stdio
objectstore-mcp --transport streamable-http --host 0.0.0.0 --port 8000
```

Example tool calls (any MCP client):

```jsonc
// Write then read a text object on the zero-infra local store
{"tool": "objectstore_create_bucket", "arguments": {"bucket": "notes"}}
{"tool": "objectstore_put_object",    "arguments": {"bucket": "notes", "key": "todo.md", "data": "- ship it"}}
{"tool": "objectstore_get_object",    "arguments": {"bucket": "notes", "key": "todo.md"}}

// Preview then execute a prefix-scoped delete on a named S3 store
{"tool": "objectstore_delete_objects_by_prefix", "arguments": {"store": "media", "bucket": "media-prod", "prefix": "tmp/"}}
{"tool": "objectstore_delete_objects_by_prefix", "arguments": {"store": "media", "bucket": "media-prod", "prefix": "tmp/", "dry_run": false}}

// Expire scratch objects after 7 days
{"tool": "objectstore_put_bucket_lifecycle", "arguments": {"store": "media", "bucket": "media-prod", "rules": [{"id": "scratch-7d", "prefix": "scratch/", "expiration_days": 7}]}}
```

## Governed capability contract

This package ships a compact canonical skill surface with specialist procedures
kept as referenced workflows. The current MCP tools, skill metadata,
`connector_manifest.yml`, ontology, mappings, shapes, fixtures, migrations,
tool-schema fingerprints, and certification metadata form one versioned
capability contract. Validate them together; do not rely on stale tool names or
historical per-task skill wrappers.

Runtime endpoints, credentials, certificate trust, tenant identity, retention,
and observability policy are deployment inputs and are never packaged values.
See [Configuration, trust, and privacy](docs/configuration.md) before enabling a
network transport, connector ingestion, Arbora delegation, or trace export.
