| `CONN-OBJECTSTORE-MCP-R001` | **Serve every store through the SDK backends.** The connector deletes `objectstore_mcp/api/api_client_base.py` and the four `api_client_*` backend modules. `objectstore_mcp/auth.py` builds each backend with `create_backend` from `scion_sdk.storage` (`SCION-CENTRALIZED-CAPABILITIES-R042.6`). `objectstore_mcp/config.py` parses `OBJECTSTORE_STORES` with `parse_stores` and keeps the implicit `local` filesystem store. It also keeps the tool-layer `Limits`. The tool layer catches `StorageError` and maps its `code` to the tool error. Store credentials move to the store `credentials` map as secret references. The ambient provider profile and the `profile` field are removed in the same release. Caller chain: MCP `tools/call` → the tool function in `objectstore_mcp/mcp/mcp_objectstore.py` → `get_backend` (objectstore_mcp/auth.py:78) → `create_backend` in the SDK. Shape: `objectstore_mcp/api/__init__.py` re-exports the SDK names the tool layer uses; no backend class stays in the package. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042`. | `tests/test_sdk_backends.py::test_tools_route_through_sdk_backends_and_no_local_copy` (planned in `test-spec.md`). A tool call on a filesystem store returns the object. `objectstore_mcp/api/` holds no class with a `backend_type`. |
| `CONN-OBJECTSTORE-MCP-R002` | **Take the provider libraries from the SDK extras.** `pyproject.toml` pins the SDK release that carries the storage backends. The connector extras `s3`, `gcs` and `azure` name the SDK extras `storage-s3`, `storage-gcs` and `storage-azure`. The connector pins no provider library itself. Caller chain: `pip install objectstore-mcp[s3]` → the SDK extra → the provider library imported by `S3Backend`. Shape: edit `[project.dependencies]` and `[project.optional-dependencies]`; relock `uv.lock`. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042`. | `tests/test_sdk_backends.py::test_extras_name_the_sdk_storage_extras` (planned in `test-spec.md`). Each connector extra names exactly one SDK storage extra and no provider library. |
| `CONN-OBJECTSTORE-MCP-R003` | **Accept WebDAV stores.** A store with backend `webdav` builds the SDK `WebDavBackend` (`SCION-CENTRALIZED-CAPABILITIES-R042.5`). Its `endpoint` is the collection root URL. Its `credentials` map holds `username` and `password` references. The object tools then work on that file share. Presign and metadata tools return the SDK refusal `STORAGE_UNSUPPORTED`. Caller chain: `get_backend` (objectstore_mcp/auth.py:78) → `create_backend` → `WebDavBackend`. Shape: no connector code beyond configuration; the test pins the routing. Depends on: `CONN-OBJECTSTORE-MCP-R001`, `SCION-CENTRALIZED-CAPABILITIES-R042.5`. | `tests/test_sdk_backends.py::test_webdav_store_routes_through_sdk` (planned in `test-spec.md`). A `webdav` store builds a `WebDavBackend`. A presign call returns `STORAGE_UNSUPPORTED`. |
