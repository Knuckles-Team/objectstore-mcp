# CONN-OBJECTSTORE-MCP — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-OBJECTSTORE-MCP-R001` | **Serve every store through the SDK backends.** The connector deletes `objectstore_mcp/api/api_client_base.py` and the four `api_client_*` backend modules. `objectstore_mcp/auth.py` builds each backend with `create_backend` from `scion_sdk.storage` (`SCION-CENTRALIZED-CAPABILITIES-R042.6`). `objectstore_mcp/config.py` parses `OBJECTSTORE_STORES` with `parse_stores` and keeps the implicit `local` filesystem store. It also keeps the tool-layer `Limits`. The tool layer catches `StorageError` and maps its `code` to the tool error. Store credentials move to the store `credentials` map as secret references. The ambient provider profile and the `profile` field are removed in the same release. Caller chain: MCP `tools/call` → the tool function in `objectstore_mcp/mcp/mcp_objectstore.py` → `get_backend` (objectstore_mcp/auth.py:78) → `create_backend` in the SDK. Shape: `objectstore_mcp/api/__init__.py` re-exports the SDK names the tool layer uses; no backend class stays in the package. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042`. | `tests/test_sdk_backends.py::test_tools_route_through_sdk_backends_and_no_local_copy` (planned in `test-spec.md`). A tool call on a filesystem store returns the object. `objectstore_mcp/api/` holds no class with a `backend_type`. |
| `CONN-OBJECTSTORE-MCP-R002` | **Take the provider libraries from the SDK extras.** `pyproject.toml` pins the SDK release that carries the storage backends. The connector extras `s3`, `gcs` and `azure` name the SDK extras `storage-s3`, `storage-gcs` and `storage-azure`. The connector pins no provider library itself. Caller chain: `pip install objectstore-mcp[s3]` → the SDK extra → the provider library imported by `S3Backend`. Shape: edit `[project.dependencies]` and `[project.optional-dependencies]`; relock `uv.lock`. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042`. | `tests/test_sdk_backends.py::test_extras_name_the_sdk_storage_extras` (planned in `test-spec.md`). Each connector extra names exactly one SDK storage extra and no provider library. |
| `CONN-OBJECTSTORE-MCP-R003` | **Accept WebDAV stores.** A store with backend `webdav` builds the SDK `WebDavBackend` (`SCION-CENTRALIZED-CAPABILITIES-R042.5`). Its `endpoint` is the collection root URL. Its `credentials` map holds `username` and `password` references. The object tools then work on that file share. Presign and metadata tools return the SDK refusal `STORAGE_UNSUPPORTED`. Caller chain: `get_backend` (objectstore_mcp/auth.py:78) → `create_backend` → `WebDavBackend`. Shape: no connector code beyond configuration; the test pins the routing. Depends on: `CONN-OBJECTSTORE-MCP-R001`, `SCION-CENTRALIZED-CAPABILITIES-R042.5`. | `tests/test_sdk_backends.py::test_webdav_store_routes_through_sdk` (planned in `test-spec.md`). A `webdav` store builds a `WebDavBackend`. A presign call returns `STORAGE_UNSUPPORTED`. |
| `CONN-OBJECTSTORE-MCP-R004` | **Name the SDK by its current name in every document.** `AGENTS.md`, `README.md` and `docs/` link the SDK by its current package name and site. The changelog keeps its released entries unchanged. Caller chain: none; the documents ship in the repository and the site. Shape: replace the retired name and site link in the three places. | `tests/test_sdk_backends.py::test_no_retired_sdk_name_in_package_or_docs` (planned in `test-spec.md`). The package, `AGENTS.md`, `README.md` and `docs/` hold 0 matches for the retired name. |
| `CONN-OBJECTSTORE-MCP-R002.1` | **Ship every provider library in the served image.** `[tool.pipelines.container] install_extras` installs the `s3`, `gcs` and `azure` extras into the `mcp` image target, so a configured `s3` store does not refuse with `STORAGE_DEPENDENCY_MISSING` in production. The `all` extra names the three extras without a version floor on itself. Caller chain: the release image build → `pip install objectstore-mcp[s3,gcs,azure]` → `S3Backend` imports boto3. Shape: edit `pyproject.toml` only. Depends on: `CONN-OBJECTSTORE-MCP-R002`. | `tests/test_sdk_backends.py::test_served_image_installs_every_provider_extra`. The `mcp` target installs `s3`, `gcs` and `azure`. |
| `CONN-OBJECTSTORE-MCP-R005` | **One typed tool per operation, and refusals that keep their cause.** The connector serves no `action`-routed tool. The SDK generates one tool per `ObjectStoreBackend` method; `objectstore_mcp/mcp/mcp_objectstore.py` adds one typed tool per extra operation: `objectstore_list_stores`, `objectstore_move_object`, `objectstore_delete_objects_by_prefix`, `objectstore_upload_file`, `objectstore_download_file`, `objectstore_upload_directory`, `objectstore_download_prefix`, `objectstore_ingest_buckets` and `objectstore_ingest_objects`, each with an optional `store`. `get_client` (objectstore_mcp/auth.py) keeps the SDK refusal code and message (`AUTHENTICATION ERROR: <code>: <message>`) and names an entitlement denial, instead of the bare exception type. Caller chain: MCP `tools/call` → the tool → `get_backend` → `create_backend`. Shape: the action-routed `objects`, `buckets`, `transfer` and `objectstore_ingest` tools and `objectstore_mcp/objectstore_input_models.py` are removed in the same release. Depends on: `CONN-OBJECTSTORE-MCP-R001`. | `tests/test_objectstore_mcp_validation.py::test_tool_inventory_is_typed_with_no_action_routing`, `tests/test_objectstore_mcp_validation.py::test_refusal_keeps_the_storage_cause`. No served tool has an `action` or `params_json` parameter or the `split-action` tag; an egress refusal reads `STORAGE_EGRESS_REFUSED`. |
| `CONN-OBJECTSTORE-MCP-R006` | **The safety governor wraps every tool's backend.** `objectstore_mcp/guard.py` `GuardedBackend` wraps the backend `get_backend` returns, so the SDK-generated tools and the typed tools both enforce the get, put and list caps, refuse wildcard single-object deletes, and the destructive tools (object and bucket delete, move, prefix delete with `dry_run=false`, tag and lifecycle removal) are declared destructive: the SDK guard refuses unless the live caller confirmed, passed `confirm`, or the operator set `SCION_ALLOW_DESTRUCTIVE`. Prefix deletes run as a dry run unless `dry_run=false` and are count-capped. Caller chain: tool → `get_backend` (objectstore_mcp/auth.py) → `GuardedBackend` → SDK backend. Shape: new module `objectstore_mcp/guard.py`; the backends stay pure adapters. Depends on: `CONN-OBJECTSTORE-MCP-R005`. | `tests/test_safety.py` (every test). A put over the cap, an unconfirmed destructive call and a wildcard delete each refuse, and the operator setting lets an unattended move proceed; a prefix delete without `dry_run=false` deletes nothing. |
| `CONN-OBJECTSTORE-MCP-R007` | **Manage S3 bucket lifecycle, versioning and object tags.** Typed tools `objectstore_get_bucket_lifecycle`, `objectstore_put_bucket_lifecycle` (rules with `id`, `prefix`, `enabled`, `expiration_days`, `noncurrent_expiration_days`, `abort_incomplete_multipart_days`, `transition_days`, `storage_class`), `objectstore_delete_bucket_lifecycle`, `objectstore_get_bucket_versioning`, `objectstore_put_bucket_versioning`, `objectstore_get_object_tags`, `objectstore_put_object_tags` and `objectstore_delete_object_tags` call the S3 client of an `s3` store. Any other backend refuses with `STORAGE_UNSUPPORTED`. An absent lifecycle or tag set reads as empty. A rule with no action refuses. Caller chain: tool → `_s3_client` (objectstore_mcp/mcp/mcp_objectstore.py) → `S3Backend.client`. Shape: tools only; no backend change. Depends on: `CONN-OBJECTSTORE-MCP-R005`. | `tests/test_objectstore_mcp_validation.py::test_s3_lifecycle_versioning_and_tags`, `tests/test_objectstore_mcp_validation.py::test_s3_management_refuses_on_filesystem_store`. |
| `CONN-OBJECTSTORE-MCP-R008` | **Package the complete surface.** The package serves, beside the tools: the skills `objectstore-object-operations`, `objectstore-bucket-administration`, `objectstore-data-transfer` and `objectstore-mcp-operations` rewritten for the typed tools, and the business skill `objectstore-business-asset-store` (key layout, stage tags, retention and the presigned-URL handoff of business media); the business-role prompt `prompts/objectstore_asset_librarian.json`; and an ontology whose classes roll up to core by `rdfs:subClassOf` (`:ObjectStore` and `:Bucket` under `:StorageContainer`, `:Object` under `:File`), never `owl:imports`, and that records each served tool as a `:Tool`, each skill's tools, the prompt agent's prompt, skills and tools, the tool-use contracts as `:Task` with ordered `:TaskStep`s, and the data location of the `objectstore-objects` source. Caller chain: fastmcp content serving of `skills/`, `prompts/` and `ontology/`. Shape: content files plus `connector_sources.py` mappings to the ontology classes. Depends on: `CONN-OBJECTSTORE-MCP-R005`. | `tests/test_surface_ontology.py` (every test). The ontology's tools equal the served tools; every tool a skill, the prompt or a contract names is served. |
| `CONN-OBJECTSTORE-MCP-R009` | **Adopt scion-sdk 0.10.0 import paths.** objectstore-mcp must import only paths that exist in `scion-sdk` 0.10.0 and must raise its floor to that release. The release removes the pre-layer paths without an alias (`SCION-CENTRALIZED-CAPABILITIES-R046`). Stage: dependency and import adoption. Edits, by file: `tests/conftest.py`: `scion_sdk._connector_serve` to `scion_sdk.connector (import `build_server` from the package)`. Raise the `pyproject.toml` requirement `scion-sdk[mcp]>=0.9.0` to `scion-sdk>=0.10.0,<0.11.0` with the same extras and regenerate `uv.lock`. A client built by the old factory keeps its options argument; `build_http_client(options, async_=True)` returns the async client. No wrapper, alias or fallback import stays. Caller chain: the connector entry point `objectstore_mcp` -> its modules above -> the public `scion_sdk` modules. Shape: import edits in the files named, one `pyproject.toml` edit and one lock edit; the new test reuses `ast` from the standard library. Depends on: SCION-CENTRALIZED-CAPABILITIES-R046. | Test: `tests/test_scion_sdk_0_10_imports.py::test_every_scion_sdk_import_resolves_on_the_pinned_release` (L2) parses every Python file of `objectstore_mcp` and `tests` and asserts each imported `scion_sdk` module resolves with `importlib.util.find_spec`. |
